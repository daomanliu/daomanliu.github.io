## 一、为什么单独做一页介绍

写文档和写「给人看的一页」是两件事。设计说明书（见 [错题本系统分析与设计](/#/post/错题本_系统分析与设计)）回答的是"系统怎么设计"，这一页只回答三个问题：

1. **它解决什么烦？** 抄题抄到手抽筋、整理完就吃灰、想找找不到。
2. **它怎么转？** 拍照 → AI 读题 → 确认入库 → 遗忘曲线复习，一条闭环。
3. **我凭什么信？** 30 秒录入、1/3/7/14/30 天档位、三端同步、0 次抄题手酸。

## 三、这一页的设计取舍

- **暖粉底色 + emoji**：错题本本身就是让人抵触的东西，视觉上先卸掉一半压力。
- **标题渐变 + pop 动画**：一秒内传达"这是个轻松的东西"，而不是又一份教材。
- **滚动淡入**：一屏一屏给信息，不逼人一次读完；但补了 `<noscript>` 兜底，脚本失效时内容也不会一直隐身。
- **点击冒星星**：纯彩蛋，不解决任何问题，但会让人多点两下。
- **零依赖**：一个 `index.html` + 一个 `style.css`，双击就能开，没有框架、没有构建、没有 CDN。

## 四、怎么嵌进博客的（同源 iframe）

博客正文会过一层 DOMPurify，Markdown 里直接写的 `<script>` 会被删干净，所以介绍页不能"内联"进来，只能当静态文件引：

1. 把 `index.html` 和 `style.css` 合成一份单文件，放到 `public/attachement/26_11_23/mistake-book-intro.html`；
2. 用**同源路径**的 iframe 引入——站点只放行同源地址和 B 站 / YouTube 那几十个白名单站点；
3. 顺手改了两处：品牌链接指向 `mb.daomanliu.cn`（免得在框里把博客顶掉），以及上面说的 `<noscript>` 兜底。

## 五、技术底子

- **Web**：Vue 3 + Spring Boot 3（详见设计文档那篇）
- **读题**：LLM 识别与解答，结果可采纳可丢弃
- **复习**：1/3/7/14/30 天档位，记得 / 模糊 / 忘记三档反馈
- **导出**：DOCX 或 Markdown 打包，异步生成后下载
- **部署**：数据放自己的仓库，模型用自己的 key，一键打包
- **三端**：网页、鸿蒙 App、小程序，同一套数据
